# Запуск і оновлення MedLink

Стек: Flask/Gunicorn, PostgreSQL 16, nginx. Код запуску БД винесено в `db.py`, захист і валідацію — у `security.py`.

## 7 жовтня 2026: фоновий LAN-доступ, сповіщення, міні-чат та аватари

- Локальний доступ тепер може працювати без Terminal. `StartLocal.command` встановлює користувацький LaunchAgent `com.medlink.medlink-1.local` у `~/Library/LaunchAgents`, режим HTTP; `StartVideoLocal.command` перемикає той самий сервіс на HTTPS. Автозапуск після входу в macOS, відновлення port-forward після помилки та оновлення адреси при зміні Wi-Fi IP. Mac, Docker Desktop і minikube мають працювати; закриття Terminal більше не повинно переривати доступ. При вимкненні/сні Mac сервер недоступний. Це локальний сервер, а не хостинг.
- Сервіс працює лише з існуючим context minikube. Якщо активний інший Kubernetes context, він чекає, не змінює його. Wi-Fi IP визначається через en0. При новій IP створіть новий QR. Використовуйте URL з `kubectl get deployment flask-app -n medlink -o jsonpath='{.spec.template.spec.containers[0].env[?(@.name=="PUBLIC_BASE_URL")].value}'`.
- Для вимкнення фонового сервісу: `sh scripts/stop-local-service.sh`. Видаляється лише LaunchAgent MedLink. Робочі службові скрипти, логи й режим зберігаються у `~/Library/Application Support/MedLink Local/`; логи/режим — у `.local-service/agent.log`, `agent.err`, `mode` всередині цієї папки. macOS блокує запуск LaunchAgent зі скриптів Desktop, тому інсталятор копіює лише потрібні службові файли в Application Support. Код проєкту залишається на Desktop. Після зміни службових скриптів повторно відкрийте StartLocal.command / StartVideoLocal.command, щоб оновити службову копію. Прямий `phone-preview.sh` лишився як засіб діагностики в Terminal; одночасно із фоновим HTTP його запускати не треба — порт буде зайнятий.
- HTTPS-режим використовує підготовлений локальний CA, не встановлює довіру пристроїв автоматично. Ручна довіра на iPhone/Mac для камери залишається потрібною за інструкцією нижче. Після входу в macOS при недоступному Docker/Kubernetes сервіс повторює перевірку; сам не запускає Docker і minikube.
- Сповіщення: компактні картки вгорі праворуч, доступні через role=status/alert. Успішні автоматично ховаються через 7 секунд, таймер зупиняється під час наведення/фокусу. Помилки залишаються до закриття. Повідомлення входу, реєстрації, профілю, документів та прийомів використовують один стиль. Помилки QR залишаються також у діалозі, щоб не загубитися за модальним вікном.
- Міні-чат: кнопка «Повідомлення» внизу праворуч після входу. Виберіть свого лікаря/пацієнта й пишіть без переходу з поточної сторінки. Закриття панелі зупиняє polling; зміна контакту скасовує попередні запити. Є перехід до документів, окремої сторінки та відеодзвінка. Повна бізнес-сторінка переписки залишається, історія повідомлень спільна. API й права доступу однакові для обох режимів.
- Аватарки: «Мій профіль → Нове фото → Завантажити аватар». JPEG/PNG до 2 МБ, квадратне JPEG 256×256 без EXIF, зберігається в БД і доступне обом Pod-ам. Можна видалити або замінити. Публічний аватар лікаря видно в каталозі, аватар пацієнта — власнику й пов’язаному лікарю. Змінювати можна лише своє фото, ID/роль із форми не приймаються. Міграція v5 лише додає nullable avatar BYTEA до user/doctor.
- Docker-білд успішний. v1.0.6 застосовано до локального Kubernetes після приватної резервної копії `.backups/medlink-before-v1.0.6-20261007.dump`. Міграція v5 завершена, обидва Pod-и готові. LaunchAgent активний у HTTP-режимі, LAN /livez повертає ok без запуску Terminal.
- У Chromium із вигаданими обліковими записами перевірено верхнє сповіщення входу, міні-чат → повна історія лікаря, закриття панелі, ширину 390 px без overflow та завантаження аватара 256×256 зі сповіщенням успіху.
- 66 тестів пройшли на ізольованій PostgreSQL: права аватарів, небезпечні файли, CSRF та JSON API міні-чату плюс попередні процеси. Дані робочої БД тестами не змінювалися.

### Локальний HTTPS для відеодзвінка

Камера й мікрофон браузера потребують довіреного HTTPS навіть у LAN: https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia . Просте відкриття HTTP або обхід попередження недовіреного сертифіката не замінює встановлення довіри.

1. Після оновлення образу відкрийте `StartLocal.command` для звичайного локального QR/фото/чату.
2. Для відео відкрийте `StartVideoLocal.command`. Він створює окремий локальний CA та сертифікат з поточною LAN IP у `.local-tls/`, запускає локальний nginx TLS на 8443 і port-forward на 8082, перевіряє TLS і змінює PUBLIC_BASE_URL на HTTPS. Ключі виключені з Git і Docker build context. Ніяких змін довіри пристроїв скрипт сам не робить.
3. На Mac передайте тільки `.local-tls/medlink-ca.crt` на iPhone через AirDrop або відкрийте надруковану адресу сертифіката у Safari. **Не передавайте ca.key/server.key.** На iPhone встановіть завантажений профіль у «Параметри → Загальні → VPN і керування пристроєм», потім «Загальні → Про пристрій → Довіра сертифікатам» і ввімкніть довіру тільки для **MedLink Local Development CA**. Інструкція Apple: https://support.apple.com/en-ie/102390 . Це ручне налаштування пристрою; довіра CA дозволяє перевіряти підписані ним сертифікати, тому його приватний ключ має залишатися на вашому Mac.
4. На Mac імпортуйте той самий публічний CA у Keychain Access і явно встановіть довіру для SSL. Ключ CA не імпортуйте і не передавайте.
5. Обидва учасники відкривають `https://LAN-IP:8443`, входять під своїми різними обліковими записами, відкривають чат і той самий дзвінок. Дозвольте камеру й мікрофон. Створюйте нові QR лише на актуальній HTTPS-адресі. Без довіри на телефоні відео не працюватиме.
6. При Ctrl+C локальний HTTPS зупиняється і скрипт повертає адресу HTTP:8081, якщо її не змінив інший запуск. Звичайний StartLocal.command має залишатися відкритим. При зміні Wi-Fi IP перезапустіть обидва потрібні режими. Після завершення тестування локальний CA можна видалити з довірених профілів пристроїв.

## 7 жовтня 2026: QR-кабінет, фото/PDF і робота на різних пристроях

Підтверджений обсяг: QR, мобільний кабінет, прийоми, історія та фото/документи.

- У навігації авторизованого користувача є «QR кабінету»: скануйте його камерою іншого телефона/комп’ютера і входьте під своїм обліковим записом. QR веде на `/workspace`, не містить паролів і не переносить авторизацію між пристроями. Лікар потрапляє у свій робочий кабінет, пацієнт — в особистий. Для тимчасового читання без входу лишається попередня опція доступу на 15 хвилин; вона не дозволяє записувати дані або відкривати вкладення.
- Лікар: реєстрація і вхід, контакти профілю, тижневий графік, календар власних прийомів, початок/скасування/завершення прийому, діагнози/рекомендації/ліки, внесення історії з QR, фото та документи пов’язаних пацієнтів. Право доступу вимагає запису до лікаря або його попередніх записів у медичній історії.
- Пацієнт: реєстрація і вхід, контакти профілю, пошук і запис до лікаря, скасування й перенесення майбутнього прийому, історія, експорт PDF, QR і власні фото/PDF.
- Перенесення прийому перевіряє робочий графік, майбутню дату, крок 30 хвилин, права власника й унікальність слота. Конфлікт нового часу не змінює попередній запис.
- Документи: JPEG/PNG/PDF, максимум 5 МБ на файл, 20 файлів і 20 МБ у картці. Перевіряється вміст, а не лише розширення; HTML/SVG і некоректні зображення відхиляються. PDF приймаються за сигнатурою та завершенням, віддаються лише як завантаження; повного антивірусного аналізу немає. Фотопрев’ю авторизовані, зменшені до 640 px і завантажуються ліниво. Оригінали віддаються як вкладення з no-store. Видалити можна лише власне завантаження: байти прибираються, метадані й дата видалення залишаються.
- Вкладення зберігаються в PostgreSQL BYTEA, тому доступні обом Pod-ам і входять до звичайної резервної копії БД. Міграція v3 лише додає таблицю та індекс; наявна історія й прийоми не змінюються. Нових Python-залежностей немає.
- Адаптивна навігація, контактні форми, документи та фото працюють у браузері на телефоні й комп’ютері. Телефон може вибрати камеру/галерею через системне поле файлу. Доступ із різних мереж усе одно потребує публічної HTTPS-адреси: QR сам не забезпечує мережеве підключення. Cloudflare Tunnel погоджений раніше; його API був недоступний. 7 жовтня повторна перевірка API Cloudflare знову завершилася timeout. Новий публічний доступ і фізичне сканування iPhone у цьому оновленні не підтверджені. Нову версію v1.0.4 у робочий Kubernetes у цьому оновленні не застосовували: команди наведено нижче.
- Docker-білд успішний. Перевірено 58 тестів на ізольованій PostgreSQL: усі успішні. Перевірено доступ до чужих файлів, CSRF, видалення байтів, файл понад 64 КБ, захищені прев’ю, перенесення і відкат при конфлікті. Дані робочої БД тестами не змінювалися.

## Оновлення 6 жовтня: реєстрація лікаря, записи з телефона та інтернет-доступ

Реєстрація лікаря тепер відкрита через `/registerPage?role=doctor`, без коду запрошення. Форма перевіряє дані, лікарню/спеціалізацію і пароль, зберігає хеш та створює початковий графік. Після реєстрації відкривається вхід лікаря. Новий обліковий запис не отримує автоматично доступ до чужих пацієнтів.

На сторінках профілю та історії, відкритих із QR, додано «Додати медичний запис як лікар». Гостя перенаправляє на вхід лікаря зі збереженням вибраного пацієнта. Форма `/doctor/patients/<id>/history` дозволяє додати діагноз, рекомендації та ліки з телефона. Доступ є лише у лікаря з записом пацієнта до нього або його попередніми медичними записами. Тимчасове посилання для перегляду не дає права редагування; пацієнт і сторонній лікар не можуть записувати дані. Записи з цієї форми самостійні, статус прийому не змінюють; для завершення прийому використовуйте розділ «Прийоми».

Діагностика: новий образ v1.0.2 і Wi-Fi IP уже були налаштовані, але на порту 8081 не працював port-forward. Після запуску `/livez` повернув HTTP 200. Адреса `192.168…` доступна тільки у локальній мережі. Для різних мереж підготовлено `scripts/internet-preview.sh`: тимчасовий Cloudflare HTTPS Tunnel, автоматичне налаштування PUBLIC_BASE_URL та Secure cookies, перевірка доступності, очищення лише власних процесів і повернення попередньої адреси при завершенні. Користувач окремо дозволив Cloudflare Tunnel для поточного MedLink після початкової відмови автоматичної перевірки. ## Перед першим оновленням на нову версію

1. Збережіть резервну копію наявної БД. Не видаляйте PostgreSQL volume/PVC або namespace.
2. У Secret `medlink-secrets` значення `FLASK_SECRET_KEY` має бути випадковим секретом довжиною щонайменше 32 символи. Нова версія відхиляє короткі та відомі шаблонні ключі. Для генерації власного значення:

   ```bash
   python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
   ```

   Запишіть його у власний локальний `k8s/01-secrets.yaml` (файл ігнорується Git). Не змінюйте `POSTGRES_PASSWORD`, `POSTGRES_USER` чи `POSTGRES_DB` для існуючого volume: зміна env PostgreSQL не змінює пароль наявного користувача БД.
3. Реєстрація лікаря відкрита через форму; DOCTOR_REGISTRATION_CODE більше не використовується.
4. Нова версія мігрує наявні відкриті паролі до PBKDF2-SHA256 (1 000 000 ітерацій), нормалізує email, переводить дати/час прийомів у типи PostgreSQL DATE/TIME та створює унікальний індекс активних слотів. Усі дії — одна транзакція з блокуванням між Pod-ами. Повторний запуск не перехешовує паролі.
5. Якщо є некоректні дати, дублікати активних слотів або email, які відрізняються лише регістром/пробілами, міграція зупиниться й відкотиться. Дублі не видаляються автоматично: перегляньте логи, виправте конфліктні записи після резервного копіювання, повторіть запуск.
6. На час **першої** міграції зупиніть старі Flask Pod-и, щоб старий код не записував відкриті паролі під час оновлення. Попередній образ несумісний із новим форматом паролів; повернення до нього потребує відновлення резервної копії БД.

## Ручна перевірка після білду

- Відкрити головну, пошук і реєстрацію; перевірити повідомлення про помилки форми.
- Зареєструвати пацієнта, увійти. Пароль із пробілами має працювати без обрізання.
