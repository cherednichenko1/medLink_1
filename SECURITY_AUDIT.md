## Перевірки

- 82 unittest, включно з реальною ізольованою PostgreSQL: доступ чужих пацієнтів/діалогів, CSRF, повторне використання cookie після виходу, абсолютне закінчення, відкликання QR/лікаря, реєстрація з очікуванням підтвердження, великі ID, квоти, карантин старого PDF, фото з метаданими, скрипти й шифрування PDF, таймаут парсера.
- Браузер Chrome із вигаданими акаунтами: повідомлення про вхід, мінічат/окрема переписка, мобільна ширина 390 px, аватар. Два незалежні браузерні контексти отримали відео з симульованих камер; завершення дійшло до другого учасника. Фізичний iPhone ці тести не замінюють.
- pip-audit: відомих вразливостей у зафіксованих Python-залежностях не знайдено на момент перевірки. Додано pypdf 6.19.0. Це не означає відсутності невідомих проблем або CVE системних пакетів Docker.
- Bandit: попередження розглянуто вручну. Динамічні частини SQL беруться лише із фіксованих назв таблиць/колонок/суфіксів; значення користувача передаються параметрами. Рядок PBKDF2 є схемою хешування. Subprocess використовує фіксований Python/module path без shell, файл надходить через stdin. Відомих експлуатованих ін’єкцій у цих місцях не виявлено.
- Робочі секрети пройшли базову перевірку довжини/різноманітності без показу значень; це не перевірка їх історичної компрометації.
- Маніфести прийняті Kubernetes через server dry-run.

## Залишкові ризики та межі

1. **HTTP у локальній мережі не шифрує медичні дані й пароль.** Для реальних даних потрібен HTTPS. Локальний CA треба встановити й явно довірити на кожному пристрої; до цього HTTPS може блокуватися Chrome/iOS. Production-режим: `MEDLINK_ENV=production`, HTTPS PUBLIC_BASE_URL і `SESSION_COOKIE_SECURE=true`. Reverse proxy повинен коректно повідомляти HTTPS; Gunicorn не має бути публічно доступним. Поточний локальний HTTP-режим — для тестових даних.
2. **Мережеві політики потребують CNI, що їх виконує.** У поточному minikube не виявлено Calico/Cilium; наявність YAML сама по собі не означає ізоляції. Не перебудовували кластер і не ризикували чинною БД. Потрібен окремий перехід на підтримуваний CNI та негативні мережеві тести.
3. PostgreSQL у чинному локальному стеку використовує початковий адміністративний акаунт, бо він виконує міграції. Для production потрібно розділити мігратор і runtime-role, додати TLS до БД та перевірити права на копії БД перед заміною живих облікових даних.
4. Дані БД і локальні резервні копії не мають доданого цим оновленням шифрування на рівні застосунку. Потрібні FileVault/захищений том, контроль прав, зашифровані зовнішні резервні копії та політика зберігання.
5. PDF-фільтр не є повним антивірусом/CDR; не усуває всі можливі вразливості PDF-переглядачів або оманливий вміст. Для production потрібен ізольований malware-scanner і оновлення бібліотек/контейнерів.
6. Не додано MFA, повний медичний журнал аудиту з незмінним зберіганням, політику відкликання всіх історичних зв’язків лікаря з пацієнтом, загальну квоту БД/історії повідомлень або централізований моніторинг атак. Існуючий зв’язок через завершений прийом/історію дає подальший доступ за чинною бізнес-логікою.
7. Власник QR може дозволити тимчасовий перегляд без входу. Той, хто отримав посилання, може прочитати дозволені дані до відкликання/закінчення. Вже прочитані дані неможливо відкликати; QR не надає анонімний запис до історії, чат або дзвінок.
8. Не проведено окремий pentest Docker Desktop/macOS, інших проєктів, ArgoCD або всіх системних пакетів образів. Не встановлювали публічного доступу. Код не відправляли у GitHub у цьому оновленні.

## Керування лікарями

Після оновлення всі лікарі очікують підтвердження. Спочатку незалежно перевірити особу/кваліфікацію та право роботи з пацієнтами, потім виконати локально:

```sh
kubectl -n medlink exec deployment/flask-app -- flask --app app list-doctors
kubectl -n medlink exec deployment/flask-app -- flask --app app verify-doctor --doctor-id ID
kubectl -n medlink exec deployment/flask-app -- flask --app app verify-doctor --doctor-id ID --revoke
```

ID замінити конкретним числом. Автоматично лікарів не підтверджували. Облікові записи, прийоми, історія та документи збережені. Всі користувачі повинні ввійти повторно і створити нові QR.
